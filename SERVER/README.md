# Workforce Attendance Server

This is the Node.js + Express + MongoDB backend for the workforce attendance management system.

## Features

- JWT authentication with role-based access control
- Admin-only employee accounts and profile management
- Shift configuration and employee shift assignment
- Leave type and holiday management
- Server-enforced admin/superadmin authorization for management APIs
- Employee deactivation disables the associated login; leave types are deactivated to preserve request history
- Shifts referenced by employees or attendance history cannot be deleted
- Employees can only retrieve their own profile through the individual employee endpoint
- Passwords supplied when creating employees are hashed before storage
- Correction request workflow
- Dashboard and monthly reporting endpoints
- Security headers, rate limiting, and CORS

## Setup

1. Copy `.env.example` to `.env`
2. Set `MONGODB_URI` and `JWT_SECRET` in `.env`; do not commit real credentials
3. Start MongoDB locally or configure a cloud MongoDB URI
4. Install dependencies:

```bash
npm install
```

5. Run the server in development mode:

```bash
npm run dev
```

### Create the first superadmin

Public registration only creates regular user accounts. To provision the initial superadmin, stop the server and run this from PowerShell in `SERVER`:

```powershell
$env:BOOTSTRAP_SUPERADMIN_NAME = Read-Host "Superadmin name"
$env:BOOTSTRAP_SUPERADMIN_EMAIL = Read-Host "Superadmin email"
$securePassword = Read-Host "Superadmin password (12+ characters)" -AsSecureString
$env:BOOTSTRAP_SUPERADMIN_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password
npm.cmd run create:superadmin
Remove-Item Env:BOOTSTRAP_SUPERADMIN_NAME, Env:BOOTSTRAP_SUPERADMIN_EMAIL, Env:BOOTSTRAP_SUPERADMIN_PASSWORD
$securePassword.Dispose()
```

This command connects to the configured `MONGODB_URI`, hashes the password, and refuses to create another superadmin if one already exists. Then start the server and sign in through the UI. Do not share or commit the credentials.

### Create an admin

After creating the superadmin, run this from PowerShell in `SERVER` to provision an admin account:

```powershell
$env:BOOTSTRAP_ADMIN_NAME = Read-Host "Admin name"
$env:BOOTSTRAP_ADMIN_EMAIL = Read-Host "Admin email"
$securePassword = Read-Host "Admin password (12+ characters)" -AsSecureString
$env:BOOTSTRAP_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password
npm.cmd run create:admin
Remove-Item Env:BOOTSTRAP_ADMIN_NAME, Env:BOOTSTRAP_ADMIN_EMAIL, Env:BOOTSTRAP_ADMIN_PASSWORD
$securePassword.Dispose()
```

The command requires an active superadmin to exist, hashes the password, and refuses duplicate email addresses. Then sign in through the UI with the admin email and password. Do not share or commit the credentials.

## Available API routes

- Health and authentication: `GET /api/health`, `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`
- Employees (admin): `GET/POST /api/employees`, `GET/PUT/DELETE /api/employees/:id`
- Shifts (admin): `GET/POST /api/shifts`, `PUT/DELETE /api/shifts/:id`
- Leave types (admin): `GET/POST /api/leave-types`, `PUT/DELETE /api/leave-types/:id`
- Holidays (admin): `GET/POST /api/holidays`, `PUT/DELETE /api/holidays/:id`
- Leave requests: `GET/POST /api/leaves`, `PUT /api/leaves/:id/status`
- Employee attendance: `GET /api/attendance/mine`, `POST /api/attendance/checkin`, `POST /api/attendance/checkout`
- Admin attendance: `GET /api/attendance`, `GET /api/attendance/:employeeId`
- Correction requests: employee `GET /api/correction-requests/mine` and `POST /api/correction-requests`; admin `GET /api/correction-requests` and `PUT /api/correction-requests/:id/status`
- Reports: `GET /api/reports/dashboard`, `GET /api/reports/monthly/:employeeId/:month`

Attendance check-in/check-out timestamps are generated by the server, not trusted from the browser. Employees must have an active employee profile and assigned shift. Shift schedules use each shift's IANA timezone; the currently assigned shift determines the work date, including overnight shifts. Work duration, lateness, early exit, and overtime are recalculated by the server at check-out and when a correction is approved. Employee attendance and correction endpoints scope records to the authenticated employee; only admins and superadmins can view organization-wide attendance or review corrections.

## Security

This backend follows a defense-in-depth approach, including:

- JWT authentication
- Role-based access restrictions
- Helmet headers
- CORS configuration
- Request rate limiting
- Input validation through route expectations and Mongoose models
- MongoDB schema constraints
- The server refuses to start if `JWT_SECRET` is missing
